# AugustTrainer Autoresearch Design

## Goal

Build an August-native ML autoresearch setup that can be spawned inside any training project and improve a model overnight. The trainer should inspect the project, discover how to run one experiment, define the metric and editable/protected files, then run a Karpathy-style loop until the user stops it.

The first MVP is not tied to `karpathy/autoresearch`. It borrows the core loop: edit a bounded artifact, run a time-boxed experiment, read one metric, keep improvements, revert regressions, and record the reasoning.

## User-facing behavior

From an ML project, the user can ask August to start AugustTrainer. August creates a project-local folder:

```text
augusttrainer/
  flow.md
  hypothesis-map.md
  decisions.md
  results.tsv
  results.jsonl
  runs/<run-id>/
    prompt.md
    diff.patch
    run.log
    metrics.json
    verdict.md
```

The trainer runs autonomously after writing `flow.md`. It does not pause for approval. `flow.md` is the reproducible contract: train command, metric extraction, optimization direction, editable files, protected files, dependency policy, timeout, revert rules, and logging format.

## Core loop

1. Inspect the project docs, configs, scripts, and recent git state.
2. Write `augusttrainer/flow.md` with the discovered experiment protocol.
3. Establish a baseline run and write it to `results.tsv` and `results.jsonl`.
4. Propose one hypothesis and record it in `hypothesis-map.md`.
5. Modify only files allowed by `flow.md`; install or change dependencies when the recorded hypothesis needs a new model/library and the project package manager supports it.
6. Run one experiment with timeout and redirected logs.
7. Parse the metric and compare against the current best.
8. Keep the code and dependency changes if they improve the objective; revert them if the run regresses, crashes, or cannot be scored.
9. Append decisions and artifacts.
10. Repeat until interrupted.

## Design choices

### Generic project contract

AugustTrainer discovers the project-specific protocol instead of assuming `uv run train.py`. The first run should support Python, shell, Make, and common ML entrypoints by reading project files and asking no questions unless the experiment cannot be discovered safely.

### Markdown as the control surface

`flow.md` is the equivalent of Karpathy's `program.md`, but project-local and generated by August. It is both human-readable and agent-parseable. The user can edit it later to steer future overnight runs.

### Dependency experimentation

AugustTrainer may install dependencies to try new model families, optimizers, kernels, metrics, or training utilities when that is part of a recorded hypothesis. It should prefer the project's existing package manager (`uv`, `pip`, `poetry`, `conda`, `npm`, etc.), pin or lock versions when the package manager supports it, and record the exact command plus manifest/lockfile diff in the run artifact. Dependency changes are experimental changes: keep them only with an improving result, otherwise revert them with the failed hypothesis.

### Audit-first artifacts

Every hypothesis, decision, metric, diff, and log path is recorded under `augusttrainer/`. The folder is the lab notebook, not hidden memory. Durable August project memory may summarize the shipped feature, but training results stay in the user's ML project.

## Guardrails

- The trainer must not modify files marked protected in `flow.md`.
- The trainer must not weaken or edit the metric extraction rule to make a result look better.
- The trainer may install dependencies only when `flow.md` defines a dependency policy and the dependency change is tied to a logged hypothesis.
- The trainer must redirect long training output to logs instead of flooding context.
- A crashed or unscored run is logged, reverted, and treated as not improving.
- Repeated failures should cause the trainer to narrow the search, not stop and ask whether to continue.
- The user can stop the process externally at any time; there is no built-in infinite background daemon in the MVP.

## August implementation shape

Prefer modular OpenCode extension points before core edits:

1. Add a project agent definition for `augusttrainer` that contains the loop contract and permissions guidance.
2. Add an August CLI command or script to scaffold `augusttrainer/` and launch the agent in the target project.
3. Add validation scenarios that prove the scaffolded artifact contract exists and that a fake metric loop records keep/revert decisions.

If a core CLI command is needed, keep it August-scoped and small. It should not change upstream OpenCode behavior for normal sessions.

## Validation strategy

- Static validation: `./scripts/doctor.sh` from repo root.
- Package validation: `bun typecheck` from `packages/opencode` if TypeScript code changes.
- Scenario validation: add an API-first scenario using a tiny fake ML project where the trainer writes `augusttrainer/flow.md`, runs a deterministic command, parses a metric, and records results.
- Artifact validation: inspect generated `augusttrainer/` files and verify they contain the command, metric, editable/protected files, baseline, and at least one decision.

## Upstream compatibility

This should remain an August feature. It should not alter OpenCode's default agent loop, session behavior, permissions, or validation harness. Agent files, scripts, and August-scoped commands are preferred because they are easier to preserve across upstream merges.

## Non-goals

- No distributed multi-agent swarm in the first MVP.
- No built-in GPU scheduler.
- No silent training-data or evaluation-harness mutation.
- No promise that arbitrary metrics are safe from Goodharting; the artifact trail must make metric gaming reviewable.

## Spec self-review

- Placeholder scan: no TBD/TODO placeholders.
- Consistency: the feature is generic ML autoresearch, not Karpathy-repo-only.
- Scope: first MVP is scaffold plus trainer agent loop, not a full daemon or swarm.
- Ambiguity: autonomous mode starts after `flow.md` is written and runs until externally stopped.
