# August project init

Goal: make the local August checkout usable as an intelligent OpenCode wrapper for any project directory.

## What `scripts/august init` installs

```text
target project
├── AGENTS.md                         # created only when missing
├── openspec/config.yaml              # generated by OpenSpec
└── .opencode/
    ├── opencode.jsonc                # default_agent: august, instructions: AGENTS.md
    ├── agent/august.md               # portable AugustCode primary agent
    ├── commands/opsx-*.md            # OpenSpec slash commands
    └── skills/openspec-*/SKILL.md    # OpenSpec workflow skills
```

The initializer is idempotent. It updates `.opencode/opencode.jsonc`, preserves unrelated config fields, creates `AGENTS.md` only when the project does not already have one, and does not overwrite a custom `.opencode/agent/august.md` unless that file was previously generated by August.

OpenSpec is installed through `npm exec --yes @fission-ai/openspec@latest -- init ...`, so users do not need a global `openspec` binary. Set `AUGUST_OPENSPEC_BIN=/path/to/openspec` to force a specific OpenSpec executable.

## Use in another project

From any project directory:

```bash
/path/to/august/scripts/august init
/path/to/august/scripts/august
```

Or initialize a project without changing directories:

```bash
/path/to/august/scripts/august init --project /path/to/project
/path/to/august/scripts/august --help
```

After init, restart any already-running August/OpenCode session so the new `.opencode` config, commands, agents, and skills are loaded.

## OpenSpec workflow

Use the generated OPSX commands inside an initialized project:

```text
/opsx-propose add-dark-mode
/opsx-apply add-dark-mode
/opsx-archive add-dark-mode
```

The commands create and manage OpenSpec artifacts under `openspec/changes/<change>/`.

## Portable contract

- Project-local files make the setup reproducible and commit-friendly.
- Existing user project config is preserved where possible.
- OpenSpec-generated files stay in standard OpenCode-supported locations: `.opencode/commands` and `.opencode/skills`.
- The August wrapper still launches OpenCode from the target project directory, so project-local config and instructions are the active context.
